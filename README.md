# 교외체험학습 신청 관리

학생이 신청서와 결과보고서를 작성하고, 담임, 교무부장, 교감, 교장이 4단계로 결재하는 웹앱입니다.
정적 파일만으로 동작하며 GitHub Pages에 올려 쓰고, 로그인과 저장은 Firebase가 맡습니다.

## 파일

| 파일 | 역할 |
|---|---|
| `index.html`, `styles.css`, `app.js` | 화면과 동작 |
| `firebase-config.js` | Firebase 연결 값 (직접 입력) |
| `firestore.rules` | 보안 규칙 원본 |
| `firestore.console.rules` | Firebase 콘솔에 바로 붙여넣기 쉬운 규칙 |

## 로그인 방식

- 학생: 이름, 학년, 반, 이메일, 전화번호, 비밀번호로 회원가입한 뒤 이메일과 비밀번호로 로그인합니다.
- 담임: 교직원 로그인 화면에서 직접 회원가입을 신청할 수 있습니다. 가입할 때 이름, 담임 학년, 담임 반, 아이디, 비밀번호를 입력합니다.
  - 가입 신청은 **승인 대기** 상태로 접수되고, **전체 관리자가 계정 관리 화면에서 승인해야** 로그인할 수 있습니다. 승인 전에는 어떤 데이터도 읽거나 쓸 수 없습니다.
  - 관리자는 승인하기 전에 이름, 아이디, 학년·반이 실제 담임 선생님과 맞는지 확인하세요. 거절하려면 같은 줄의 **거절**을 누릅니다. (거절해도 로그인 계정은 남으므로 같은 아이디로 다시 가입하려면 Firebase 콘솔 Authentication에서 그 사용자를 삭제해야 합니다.)
- 교직원(교무부장, 교감, 교장): 전체 관리자가 만들어 준 **아이디와 비밀번호**로 로그인합니다.
  - 처음 로그인하면 임시 비밀번호를 바꾸도록 안내합니다.
  - 로그인한 뒤에는 상단의 **비밀번호 변경**으로 언제든 직접 바꿀 수 있습니다. (현재 비밀번호 확인 필요)
  - 아이디는 실제 이메일이 아니라 내부적으로 `아이디@staff.fieldtrip.local` 형태로 저장됩니다. 그래서 이메일로 비밀번호를 찾는 기능은 없습니다. 비밀번호를 잊으면 관리자가 Firebase 콘솔에서 해당 사용자를 삭제하고 계정을 새로 만들어 주어야 합니다.

## 설정 순서 (처음 한 번)

1. [Firebase 콘솔](https://console.firebase.google.com)에서 프로젝트를 만듭니다. (Spark 무료 요금제)
2. **빌드 > Authentication > 시작하기 > 로그인 방법**에서 **이메일/비밀번호**를 사용 설정합니다.
3. **Authentication > 설정 > 승인된 도메인**에 `내아이디.github.io`를 추가합니다.
4. **빌드 > Firestore Database > 데이터베이스 만들기**로 DB를 만듭니다. 위치는 `asia-northeast3`(서울), 모드는 프로덕션 모드를 고릅니다.
5. Firestore **규칙** 탭에 `firestore.rules` 내용을 전부 붙여넣고 **게시**합니다.
6. **프로젝트 설정 > 내 앱 > 웹 앱 추가**로 앱을 등록하고, 나온 `firebaseConfig` 값을 `firebase-config.js`에 넣습니다.
7. **첫 관리자 계정**을 직접 만듭니다. (이후 교직원은 앱 안에서 만듭니다.)
   1. Authentication > 사용자 > **사용자 추가**: 이메일 `원하는아이디@staff.fieldtrip.local`, 임시 비밀번호(8자 이상). 만들어진 사용자의 **UID**를 복사합니다.
   2. Firestore에서 컬렉션 `staff`를 만들고, **문서 ID를 방금 복사한 UID**로 하여 필드를 입력합니다.
      - `id` (문자열): 원하는아이디
      - `name` (문자열): 이름
      - `step` (숫자): 0 담임, 1 교무부장, 2 교감, 3 교장
      - `canManage` (불리언): true
      - `mustChange` (불리언): true
8. 이 폴더를 GitHub 저장소에 올리고 **Settings > Pages**에서 브랜치를 선택해 배포합니다.
9. 관리자로 로그인하면 **계정 관리** 탭에서 나머지 교직원 계정(아이디, 이름, 결재 단계, 임시 비밀번호)을 만들 수 있습니다.

## 누가 무엇을 할 수 있나

- 학생: 본인 신청서만 읽고 쓰고 지울 수 있습니다. 결재가 모두 끝나기 전에는 신청서를 수정할 수 있고, 수정하면 결재가 처음부터 다시 진행됩니다. 결재가 끝나면 신청서는 고정되고 결과보고서만 쓸 수 있습니다.
- 담임: 전체 관리자의 승인을 받은 뒤, 가입할 때 입력한 학년/반과 신청서의 학년/반이 일치하는 학생 신청서만 읽고, 담임 단계만 승인하거나 취소할 수 있습니다.
- 담임은 본인 반 학생의 **반려된 신청서**를 삭제할 수 있습니다. (결재 관리 화면의 "반려 신청서 삭제", 사진과 결재 기록도 함께 지워집니다.)
- 결과보고서 검토: 학생이 결과보고서를 제출하면 **담임(또는 전체 관리자)이 승인 또는 반려**합니다. 승인되면 학생은 결과보고서를 더 이상 수정할 수 없고, 반려되면 담임 메모를 보고 고쳐서 다시 제출합니다. 결과보고서 PDF는 승인된 뒤에만 저장할 수 있습니다.
- 안내 메일: 담임이 신청서나 결과보고서를 승인/반려하면 학생이 가입할 때 쓴 이메일로 자동 안내됩니다. 설정 방법은 `mail-sender/README.md`를 보세요. `firebase-config.js`의 `mailEndpoint`가 비어 있으면 메일은 보내지 않습니다.
- 결과보고서 활동 인증 사진은 **3장 이상 6장 이하**입니다. 한 번에 여러 장을 고를 수 있고, 올린 사진은 제출 전에 삭제할 수 있습니다. 결과보고서 서식에는 한 줄에 3장씩 같은 크기로 정렬되어 나옵니다. 사진은 `photos/{신청서ID}/items/{번호}`에 저장됩니다.
- 신청서와 결과보고서는 **PDF로만** 저장합니다. (담당자 화면의 "전체 현황 엑셀"만 접수 현황 집계용으로 남아 있습니다.)
- 교무부장, 교감, 교장: 전체 신청서를 읽고, **자기 결재 단계**만 승인하거나 취소할 수 있습니다. 반려와 검토 메모는 교직원이 남길 수 있습니다.
- 전체 관리자(`canManage: true`)인 교직원: 학생/교직원 목록을 볼 수 있고, 교직원 계정을 만들거나 학생/교직원 등록을 삭제할 수 있습니다. 전체 관리자는 모든 신청서를 조회할 수 있지만 승인은 자기 결재 단계만 처리합니다.
- 삭제와 재등록: 계정 관리 화면의 **삭제/거절/등록 삭제**는 앱의 등록 정보만 지웁니다. 로그인 계정(Firebase Authentication)은 남지만 등록 정보가 없으면 아무것도 읽거나 쓸 수 없습니다.
  - 등록 정보가 없는 계정이 다시 로그인하면 **등록 정보 입력 창**이 뜹니다. 학생은 이름, 학년, 반, 전화번호를 다시 입력해 등록을 마칠 수 있고, 교직원 계정은 담임 정보로 다시 신청하면 전체 관리자의 승인을 받아야 합니다. (가입 도중 중단된 학생 계정도 같은 방법으로 복구됩니다.)
  - 학생 목록의 **신청 기록 삭제**는 그 학생의 신청서, 결재 기록, 사진을 모두 지웁니다. 학생 등록을 지워도 신청 기록은 자동으로 지워지지 않으므로 필요하면 따로 지우세요.
  - 로그인 계정 자체를 지우려면 Firebase 콘솔 Authentication > 사용자에서 삭제해야 합니다. (앱만으로는 지울 수 없습니다.)
- 비밀번호 재설정: 본인 비밀번호는 앱에서 바꿀 수 있습니다. 다른 사람의 Firebase Authentication 비밀번호를 앱에서 직접 바꾸려면 관리자 SDK가 필요한 서버 기능이 별도로 필요하므로, 현재 버전에서는 Firebase 콘솔에서 재설정하거나 사용자를 삭제 후 재가입시키는 방식으로 처리합니다.
- 위 제한은 화면이 아니라 `firestore.rules`가 서버에서 강제합니다.

## 학생 화면과 서식

- 신청서의 **학년·반은 가입할 때 입력한 값으로 고정**됩니다(수정할 수 없음). 서버 규칙도 신청서의 학년·반이 가입 정보와 다르면 저장을 거부합니다. 반이 바뀌면 전체 관리자가 학생 정보를 고쳐야 합니다(현재 화면에는 학생 정보 수정 기능이 없으므로, 학생 등록을 삭제하고 학생이 새 정보로 다시 등록합니다).
- **비밀번호**: 학생은 로그인 화면의 "재설정 메일 받기"로 비밀번호를 다시 정하고, 로그인한 뒤에는 "비밀번호 변경"으로 직접 바꿀 수 있습니다. (교직원은 가짜 이메일을 쓰므로 재설정 메일이 없고 관리자가 처리합니다.)
- **공휴일·휴업일**: 일별 학습계획은 주말과 등록된 날짜를 제외하고 만들어집니다. 전체 관리자는 "계정 관리" 화면의 "공휴일·휴업일 관리"에서 날짜를 추가하거나 삭제합니다. 기본으로 2026년 10월 이후의 일부 공휴일(개천절 대체공휴일, 한글날, 성탄절, 2027년 신정)이 들어 있습니다. **그 밖의 공휴일과 재량휴업일은 직접 등록하세요.**
- **결재란**: 신청서와 결과보고서 서식(미리보기와 PDF) 맨 위에 담임, 교무부장, 교감, 교장의 결재란이 있고, 승인한 사람의 이름과 날짜가 들어갑니다.
- 휴대폰에서는 서식의 표가 항목별 카드로 바뀌어 세로로 입력합니다.

## 한글(HWPX) 저장

PDF와 같은 조건으로(최종 결재 후, 결과보고서는 담임 승인 후) **신청서와 결과보고서를 한글 파일(.hwpx)로도 저장**할 수 있습니다. 학생 화면과 결재 화면에 "한글 저장" 버튼이 있습니다.

- 결재란, 표 서식, 일별 학습계획, 결과보고서의 활동 인증 사진(한 줄에 3장)이 들어갑니다.
- 한글 2024에서 열리는 것과 모양을 확인했습니다. 다른 버전의 한글에서는 확인하지 못했습니다.
- 파일 만드는 코드는 `hwpx.js`, 글꼴·글자 모양 정의는 `hwpx-assets/header.xml`(한글에서 저장한 서식 파일)입니다. 서식을 바꾸려면 `hwpx.js`를 고칩니다.
- 한글에서 PDF와 모양이 조금 다를 수 있습니다. (표 안의 줄바꿈과 글꼴 크기는 한글이 계산합니다.)

## 운영 점검 (배포 뒤 한 번)

### API 키를 우리 사이트에서만 쓰도록 제한
`firebase-config.js`의 apiKey는 공개되지만, 다른 곳에서 마음대로 쓰지 못하게 제한할 수 있습니다.

1. [구글 클라우드 콘솔 > API 및 서비스 > 사용자 인증 정보](https://console.cloud.google.com/apis/credentials)에서 프로젝트 `field-trip-e5c30`을 고릅니다.
2. **Browser key (auto created by Firebase)** 키를 엽니다.
3. **애플리케이션 제한사항**에서 **웹사이트**를 고르고 아래 주소를 모두 추가합니다. (로그인 처리와 비밀번호 재설정 링크에 쓰입니다.)
   - `https://knue20-kmla.github.io/*`
   - `https://field-trip-e5c30.firebaseapp.com/*`
   - `https://field-trip-e5c30.web.app/*`
4. **API 제한사항**은 **키 제한 안 함**으로 두는 것이 안전합니다. (잘못 제한하면 로그인이 막힙니다.)
5. 저장한 뒤 사이트에서 로그인, 신청서 제출이 되는지 확인합니다. 안 되면 제한 설정을 되돌리세요. 설정이 반영되는 데 몇 분 걸릴 수 있습니다.

### 사용량 확인
무료(Spark) 요금제에는 결제 계정이 없어서 **예산 알림이 없습니다.** 대신 무료 한도를 넘으면 서비스가 멈출 뿐 요금이 청구되지 않습니다. Firebase 콘솔 **Firestore Database > 사용량** 탭에서 일일 읽기·쓰기와 저장 용량(1GB)을 가끔 확인하세요. 한도가 부족해지면 사진 크기를 줄이거나 지난 학년 기록을 삭제합니다.

## 개인정보 안내

이름, 학번, 연락처, 사진이 Firebase(구글 클라우드)에 저장됩니다. 학교의 개인정보 처리 방침과 보호자 동의 절차에 맞는지 먼저 확인하세요.
